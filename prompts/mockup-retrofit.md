# 構造化プロンプト（Ichiki 制約準拠）

既存の HTML（見た目は合意済みで、Ichiki の宣言 `data-*` だけが無いもの）に  
宣言を後付けするときに、対象ページとあわせて渡す。**この作業を「構造化」と呼ぶ。**

前提: 合意デザインは `.ichiki/mockup-before/` に退避済みであること  
（`docs/022-既存htmlからモックアップを作る.md` の手順1）。無ければ先にそちらを済ませる。

**規約はこのファイルに書かない。`rules/vocabulary.md` が唯一の正である。**  
理由は `prompts/mockup-generation.md` と同じ（要約・抜粋を2箇所に置くと語彙が  
育つたびにズレる）。

---

## 対象ページ（埋める）

```
以下のページを構造化してください:
  - about/spots.html
  - about/spots/hiraodai.html
```

ページ名の代わりに、ディレクトリを指定してまとめて頼んでもよい。

```
.ichiki/mockup-before/about/ 以下の全ページを構造化してください。
```

---

### ここから下をAIに渡す

あなたは、見た目が合意済みの既存モックに Ichiki の制約語彙（`data-*` 宣言）を  
後付けする「構造化」を行います。  
**やり取り・説明・出力メッセージはすべて日本語で書いてください。**

**新規にデザインするのとは違います。見た目は1ピクセルも変えてはいけません。**  
構造（何が編集対象か・何が CPT か・どこが共通か）だけを、宣言として足します。

## 1. まず規約を読む

**`.claude/ichiki/rules/vocabulary.md` を最初に読んでください。**  
そこに書かれた宣言（`data-*`）とルール（L01〜L31）が守るべき全てです。  
**推測させないでください。** 宣言が無いものは変換器がエラーで停止します。

## 2. 対象ページごとに宣言を足す

各ページについて、`.ichiki/mockup-before/` にある対応するページ（同じ相対パス）を  
**見た目の正**として見比べながら、HTML構造・class名・文言・画像は一切変えず、  
`data-*` 属性だけを足してください。

迷ったら `.ichiki/mockup-before/` 側が正です。そちらに無い装飾やクラスを  
足してはいけません。

## 3. lint が通るまで直す

```bash
node .claude/ichiki/bin/ichiki.js lint <mockupDir>
```

**一発で完璧に書こうとしないでください。** lint の指摘がそのまま作業リストになります。  
error が 0 になるまで繰り返してください。

## 4. 見た目が変わっていないことを確認する

```bash
node .claude/ichiki/bin/ichiki.js serve .ichiki/mockup-before 18081 &
node .claude/ichiki/bin/ichiki.js diff . http://localhost:18081
```

バックグラウンドでコマンドを実行できるなら、`serve` を先に裏で動かしてから  
`diff` を実行してください（できないなら、ここだけ人に投げてよいと報告してください）。

差分が出たら、宣言を足す以外のことをしています。3 に戻って直してください。  
**一覧ページだけは差分が大きく出ます。** モックが見本を複数並べているのに対し、  
実サイトは実際の投稿数しか出さないためで、レイアウトの不具合ではありません。

## 5. 終わったら報告する

対象にしたページごとに次を報告してください。

- `lint` の error が 0 になったか
- `diff` の差分が許容範囲か（一覧ページの投稿数差以外に差分が無いか）
- vocabulary.md のルールが実態に合わないと感じた箇所（**勝手に回避せず報告**。  
  語彙を直すかどうかは人が決めます）
