# AI に書かせて lint を通す

> [案件のトップに戻る](../../../README.md)（やりたいことから探せます）

新規にモックを書くときも、構造化（既存 HTML への宣言の後付け）をするときも、
**AI に書かせて lint を通すまでの回し方は同じです。** ここにまとめます。

- 新規に書く → [021-モックアップを作る.md](021-モックアップを作る.md)
- 構造化する → [022-既存htmlからモックアップを作る.md](022-既存htmlからモックアップを作る.md)

---

## 覚えるコマンドは1つ

```bash
node .claude/ichiki/bin/ichiki.js lint .
```

`total: error=0` なら OK です。error が出ている間は先に進めません（変換が止まります）。

---

## AI に書かせる

モックには決まった書き方（制約語彙）があります。**それを守らないと WordPress にできません。**
覚える必要はありません。AI に読ませてから書かせてください。

**ページ名は列挙してください。** 単数の書き方だと、複数ページ頼みたいときに
どう書けばいいか迷います。1枚でも複数でも、書き方は同じにしておきます。

### 新規に書くとき

Claude Code に、こう頼みます。

```
.claude/ichiki/prompts/mockup-generation.md を読んで、その指示どおりに
以下のページを作ってください。出力はすべて日本語で書いてください。

- about/index.html
- about/spots.html
- about/spots/hiraodai.html
```

このプロンプトが「先に規約を読む → 書く → lint が通るまで直す」まで面倒を見ます。
**デザイン（色・レイアウト・雰囲気）は自由**という前提で書かれています。
構造化のときは前提が違うので、下の書き方を使ってください。

### 構造化するとき

デザインは既に決まっている（**変えてはいけない**）ので、規約だけを読ませ、
合意デザイン（`.ichiki/mockup-before/`）を見た目の正として指定します。

```
.claude/ichiki/rules/vocabulary.md を読んでください。
.ichiki/mockup-before/ 以下と見た目が変わらないように、以下のページに
宣言（data-*）を付けてください。終わったら lint を通してください。
出力はすべて日本語で書いてください。

- about/spots.html
- about/spots/hiraodai.html
```

ページ名の代わりに、ディレクトリを指定してまとめて頼んでも構いません。

```
.claude/ichiki/rules/vocabulary.md を読んでください。
.ichiki/mockup-before/about/ 以下の全ページに、見た目を変えずに宣言（data-*）を
付けてください。終わったら lint を通してください。出力はすべて日本語で書いてください。
```

### 既にあるページ（構造化済み）を直すとき

```
.claude/ichiki/rules/vocabulary.md を読んでから、about/spots.html の
セクションを1つ足してください。終わったら lint を通してください。
出力はすべて日本語で書いてください。
```

規約を読ませずに直させると、宣言（`data-acf` など）が静かに消えます。
見た目は変わらないので、**変換するまで気づけません。**

## 詰まったとき

### lint に error が出た

行番号とルール番号（`L03` など）が出ます。意味は
[`rules/vocabulary.md`](../rules/vocabulary.md) の一覧にあります。

AI に貼れば直せます。

```
lint でこう出ました。vocabulary.md を読んで直してください。
<lint の出力を貼る>
```

### warn がたくさん出る

`L20`（`data-acf` の無いテキスト）は **error ではありません**。
「更新できない固定文言」の一覧です。**お客様と「ここは変えられません」と
合意するためのもの**なので、消そうとしなくて構いません。

ただし目は通してください。「ここも変えたい」と言われる箇所が混じっていることがあります。
