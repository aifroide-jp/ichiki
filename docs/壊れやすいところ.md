# 壊れやすいところ

> [Ichiki の README に戻る](../README.md)

Ichiki を直すときに読んでください。**同じ壊れ方を何度もしている**ので、
パターンとして書き出します。すべて実際に踏んだものです。

---

## 1. 同じことを2箇所が別々に知っている

**いちばん多い壊れ方です。** 片方だけ直されて、静かにズレます。

| 実際に起きたこと | どうなったか |
|---|---|
| scan と変換器が別々にモックを読んでいた | デフォルト値が**39件**ズレた。全部 scan 側の誤り |
| lint と変換器が別々にファイルを探していた | 除外がズレて「lint は通るが変換で落ちる」 |
| `compare.js` と `diff.js` が同じ比較をしていた | 片方は一度も成功していなかった |
| `nkk_page_slug` が2箇所にあった | 片方だけ `_`→`-` 変換を忘れ、リンクが `href=""` に |
| testspec が HTML を正規表現で読んでいた | 見出しを日本語にしただけで壊れた |

**直し方**: `src/shared/` に1つ置いて両方から使う。
表示（人が読む）と機械可読（JSON）は分ける。

**検査**: `test/check-rule-sync.js` が語彙と lint のズレを見る。
`--acf-map` が台帳と生成物のズレを見る。

---

## 2. 推測している

宣言があるのに読まず、名前や構造から当てている箇所。

| 実際に起きたこと | どうなったか |
|---|---|
| testspec がテーマの PHP を解析してページ種別を推測 | 12ページ中**11ページ**が「種別不明」 |
| `{ news:'nkk_news', events:'nkk_event' }` が本体に焼き込まれていた | 他案件で効かない |
| プロジェクト名を「2つ上のディレクトリ名」から導出 | モックを移した瞬間 `Documents` になった |
| テーマ名を `theme_dir`（環境依存の絶対パス）から導出 | 本番のテーマ名が `nkk-poc` になった |
| 区切り文字を `' | '` `' - '` `' – '` の順に試す | 推測。宣言か設定にすべき |

**直し方**: 宣言（`data-*`）か設定（`.ichiki.json`）から取る。
導出できないなら**止める**。黙って既定値に落とさない。

---

## 3. 既定値が案件の値になっている

引数を渡している限り表に出ません。**省いた瞬間に他案件で違う先を見ます。**

```js
const SITE = (args[1] || 'http://localhost:10004')      // 検証案件のポート
path.join(ROOT, 'mockup-real')                          // 移設で消えたディレクトリ
```

**直し方**: 既定は `.ichiki.json` から取る。無ければ「引数で渡すか設定に書け」で止める。

**検査**: `grep -rn "localhost:1[0-9]\{4\}" src/` で焼き込みが見つかる。

---

## 4. 検査が通っていても検査自体が壊れている

**通ったから正しい、ではありません。**

| 実際に起きたこと | どうなったか |
|---|---|
| フィールド突合が名前で照合、出力はキー指定 | **3/327** で「通った」と言い続けていた |
| `gate --visual` が引数なしで呼んでいた | 一度も成功していない。`blocking:false` で気づけない |
| testspec が存在しないパスのレポートを読んでいた | 常に「未実行」に縮退。安全側なので気づけない |
| 凍結が日付で毎日落ちる | 「また落ちてる」で `--update` が惰性になる |

**直し方**: `test/verify-rules.js`（負のテスト）で「全ルールが実際に違反を検出できるか」を見る。
縮退（安全側に倒れる）実装は、縮退したことを**出力に出す**。

---

## 5. 通ったステップの警告が消える

`gate` は各段の出力を捨てます。`warn` にしただけでは誰にも見えません。

> 実測: デフォルト値の食い違い39件を `warn` にしたが、gate には `✓` としか出ず、
> 「問題が出るようにした」つもりで隠れていた。

**直し方**: 通った段でも警告の**件数**を出す。件数は各段の自己申告（`警告 N 件`）を採る
（行を数えると見出しまで数える）。

---

## 6. 生成物が「それらしく」見えて壊れている

文字列フィールドは ACF がデフォルト値を返すので、**壊れていても画面は正しく見えます。**

| 実際に起きたこと | 気づいた理由 |
|---|---|
| `get_field()` に投稿 ID が無い（36箇所） | 画像だけ壊れた（image 型はデフォルトを持てない） |
| 画像がメディアライブラリに入らない | 同上 |
| url 型のデフォルトがページ相対 | 全ページ `href="http://../contact/"`。**ピクセル比較では出ない** |

**直し方**: `verify:live` で実サイトを見る。`diff` でピクセルを見る。
生成物を読むだけでは足りません。

## テストを厚くしている場所

上の裏返しです。

| | 何を守っているか |
|---|---|
| `test/verify-rules.js` | 全ルールが違反を検出できる（検査自体の検査） |
| `test/check-rule-sync.js` | 語彙と lint の同期 |
| `test/run.js` | scan の回帰（fixture ↔ expected） |
| `ichiki snapshot` | 出力の凍結。**ページを1枚足したとき既存が動かないこと**を見る |
| `--acf-map` の突き合わせ | 台帳と生成物のズレ。1件でも違えば停止 |
| `verify:live` | 宣言が実サイトに出ているか |

**凍結が効く理由**: 13ページ目を足すと、増えるのはそのページの3ファイルだけで、
既存12ページのテンプレートと ACF は1つも変わりません。
変わるのは集約ファイル（`functions.php` / `seed-*.php`）だけです。
つまり「既存ページが動いたら事故」という信号が取れます。
