# 既存の HTML からモックアップを作る（構造化）

> [案件のトップに戻る](../../../README.md)（やりたいことから探せます）

**見た目は合意済みで、宣言（`data-*`）だけが無いモック**が降りてくることがあります。
そこに宣言を後付けする作業を**構造化**と呼びます。

書き方・lint の通し方・詰まったときの対処は
[023-AIに書かせてlintを通す.md](023-AIに書かせてlintを通す.md) にまとめてあります。
**この文書には、構造化のときだけ違うことを書きます。**

---

## 普段と違うのは1点だけ

**見た目が変わってはいけません。**

新規に書くときは、合意までに見た目が変わるのが正しい動きです。
構造化は宣言を足すだけなので、変わったら何かを壊しています。

だから最後にピクセルで比べます。

---

## 手順

### 1. 合意デザインを退避する

```bash
mkdir -p .ichiki
git mv <ルートのページ一式> .ichiki/mockup-before/
```

以降**ここは触りません**。見た目の正なので、比較の基準になります。

`.ichiki/` の下に置くのは、隠しディレクトリが走査から外れるためです。
ルートに置くとモックの一部として読まれ、構造化していないページで lint が大量に落ちます。

### 2. ルートに構造化したモックを置く

宣言を後付けしたものをルートに置きます。**1ページずつで構いません。**

AI への頼み方は [023-AIに書かせてlintを通す.md「構造化するとき」](023-AIに書かせてlintを通す.md#構造化するとき)
を見てください。規約を読ませて宣言を付けさせ、`ichiki lint` を通します。

### 3. 途中であることを宣言する

`.ichiki/mockup-before/` があれば `ichiki scan` が自動で書きます。手で書くならこうです。

```jsonc
"retrofit": {
  "before": ".ichiki/mockup-before",
  "note": "構造化が途中。残りのページは合意デザインにしかない"
}
```

宣言すると4つ変わります。

| | |
|---|---|
| 置き場所 | 規約から外れていてよい（**宣言された逸脱**として扱う） |
| 未解決リンク | 警告に落ちる。構造化していないページへのリンクは必ず出るため |
| `ichiki doctor` | 構造化前 N ページ / 構造化済み M ページ を数える |
| 生成したテーマ | 管理画面に「変換途中です」と出す |

**終わったら消してください。** 消し忘れると未解決リンクが黙って許され続けます。
`doctor` が毎回言うので気づけます。

### 4. 見た目が変わっていないことを確かめる

```bash
node .claude/ichiki/bin/ichiki.js serve .ichiki/mockup-before 18081 &
node .claude/ichiki/bin/ichiki.js diff . http://localhost:18081
```

> **Windows（PowerShell）** では末尾の `&` はバックグラウンド起動になりません。
> ターミナルを2枚開き、1枚目で `serve` を動かしたまま、2枚目で `diff` を叩いてください。
>
> ```powershell
> # 1枚目（開いたままにする）
> node .claude/ichiki/bin/ichiki.js serve .ichiki/mockup-before 18081
>
> # 2枚目
> node .claude/ichiki/bin/ichiki.js diff . http://localhost:18081
> ```

差分が出たら、宣言を足す以外のことをしています。

> 一覧ページだけは差分が大きく出ます。モックが見本を何枚も並べているのに対し、
> 実サイトは実際の投稿数しか出さないためです。レイアウトの不具合ではありません。

---

## 途中でも WordPress まで通してください

全ページ構造化し終わるまで待つ必要はありません。**少数のページで先に通すのが正しい順序**です。

> 実測: 変換器の欠陥（フィールドの出力漏れ・画像がメディアに入らない・
> `<title>` が内部識別子になる・フォームの死にフィールド）は、
> 一部のページを WordPress 化した時点で見つかりました。
> 全部やり終えてからだと、全部あとで直すことになります。

「WordPress が出ると完成に見える」ほうは、管理画面の警告で潰してあります。

---

## どれくらいかかるか

> 実測: 710行のページ1枚で、lint error 37件 → 0件、宣言139箇所、**7分**。
> 見た目の差は249px（フォント要因のみ）。
> 工程の大半は共通領域のコピーと `<style>` の分離で、
> 意味を考えるのは `data-acf` の命名だけでした。

ページ数を掛ければ見積もれます。
