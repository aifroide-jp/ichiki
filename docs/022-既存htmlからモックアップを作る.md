# 既存の HTML からモックアップを作る（構造化）

> [案件のトップに戻る](../../../README.md)（やりたいことから探せます）

**見た目は合意済みで、宣言（`data-*`）だけが無いモック**が降りてくることがあります。  
そこに宣言を後付けする作業を**構造化**と呼びます。

**見た目は1ピクセルも変えてはいけません。** [021](021-モックアップを作る.md)  
（新規に書くとき）と違い、合意までに見た目が変わるのは正しくありません。  
宣言を足すだけの作業なので、変わったら何かを壊しています。

---

## 1. 合意デザインを退避する（最初に1回だけ）

```bash
mkdir -p .ichiki
git mv <ルートのページ一式> .ichiki/mockup-before/
```

以降**ここは触りません**。見た目の正なので、比較の基準になります。

`.ichiki/` の下に置くのは、隠しディレクトリが走査から外れるためです。  
ルートに置くとモックの一部として読まれ、構造化していないページで lint が大量に落ちます。

---

## 2. Claude Code に構造化させる

以下のファイルを指定して実行としてください。

```
.claude/ichiki/prompts/mockup-retrofit.md を読んで、その指示どおりに
以下のページを構造化してください。

- about/spots.html
- about/spots/hiraodai.html
```

複数ファイルではなくディレクトリで指定してもよい。

```
.claude/ichiki/prompts/mockup-retrofit.md を読んで、その指示どおりに
.ichiki/mockup-before/about/ 以下の全ページを構造化してください。
```

宣言の付け方・lint を通すところ・見た目が変わっていないことの確認まで、  
このプロンプトが面倒を見ます。**`css/` `js/` `images/` はルートに実体が無いと  
ページから見えないので、このプロンプト自身がページ単位でコピー・抽出まで  
行います**（`.ichiki/mockup-before/` に置いたままでは通りません）。

---

## 3. 途中であることを宣言する（自動）

`.ichiki/mockup-before/` があれば `scan` が自動で `.ichiki.json` に書きます。  
手で書くならこうです。

```jsonc
"retrofit": {
  "before": ".ichiki/mockup-before",
  "note": "構造化が途中。残りのページは合意デザインにしかない"
}
```

宣言すると4つ変わります。

| | |
|---|---|
| 置き場所 | 規約から外れていてよい（**宣言された逸脱**として扱う） |
| 未解決リンク | 警告に落ちる。構造化していないページへのリンクは必ず出るため |
| `doctor` | 構造化前 N ページ / 構造化済み M ページ を数える |
| 生成したテーマ | 管理画面に「変換途中です」と出す |

**終わったら消してください。** 消し忘れると未解決リンクが黙って許され続けます。  
`doctor` が毎回言うので気づけます。

---

## 途中でも WordPress まで通してください

全ページ構造化し終わるまで待つ必要はありません。**少数のページで先に通すのが正しい順序**です。

> 実測: 変換器の欠陥（フィールドの出力漏れ・画像がメディアに入らない・  
> `<title>` が内部識別子になる・フォームの死にフィールド）は、  
> 一部のページを WordPress 化した時点で見つかりました。  
> 全部やり終えてからだと、全部あとで直すことになります。

「WordPress が出ると完成に見える」ほうは、管理画面の警告で潰してあります。

---

## どれくらいかかるか

> 実測: 710行のページ1枚で、lint error 37件 → 0件、宣言139箇所、**7分**。  
> 見た目の差は249px（フォント要因のみ）。  
> 工程の大半は共通領域のコピーと `<style>` の分離で、  
> 意味を考えるのは `data-acf` の命名だけでした。

ページ数を掛ければ見積もれます。
