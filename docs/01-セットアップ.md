# Ichiki を使えるようにする

> [案件のトップに戻る](../../../README.md)（やりたいことから探せます）

案件のリポジトリで **1回だけ**やる作業です。終われば、あとはコマンドを叩くだけになります。

---

## 事前に入れておくもの（Mac / Windows 共通。この2つだけ）

| | 何のため | 入手先 |
|---|---|---|
| Node.js 24+ | Ichiki 自体の実行（node で書かれている） | [node LTS版](https://nodejs.org/ja) |
| Local | WordPress の開発環境。サイト起動と PHP をこれ1つでまかなう | [Local](https://localwp.com/) |

git は既に入っている前提（無ければ、下のセットアップコマンドが入れ方を案内して止まる）。

---

## Local でサイトを用意する

Ichiki のセットアップの前に、この案件用の WordPress サイトを Local に作っておきます。
（**これは Ichiki の作業ではありません。** Local 側の準備です）

1. Local を開き、**サイトを新規作成**します（コンテナ名を決める。案件名と同じでなくて構いません）。
2. PHP・Webサーバー（Apache/Nginx）・データベースを選び、WordPress 環境を作ります
   （迷ったら既定のままで構いません）。
3. 作ったサイトを右クリック →「**Site folder**」（または「Go to site folder」）を選ぶと、
   そのサイトのフォルダが Finder / エクスプローラーで開きます。アドレスバーのパスを
   コピーしてください。下の「やること」で使います。

   例えば開いたパスが `/Users/…/Local Sites/mysite` なら:

   | この案件が使う値 | 値 |
   |---|---|
   | `wp_root` | `/Users/…/Local Sites`（サイト名より上の部分） |
   | `local_site_container` | `mysite`（そのフォルダ自身の名前） |

`site_url` は Local が自動で決めます。**基本は変えなくて構いません。**
手元の環境でポートが競合していたら、Local 側でポートを確認してから書き換えてください。

## やること

```bash
# 0. 案件のリポジトリのルートに移動する
cd <案件のリポジトリ>

# 1. 取り込む
git submodule add https://github.com/aifroide-jp/ichiki .claude/ichiki
git submodule update --init --recursive

# 2. 残りは1コマンド
node .claude/ichiki/bin/ichiki.js setup
```

**このコマンドの途中で、`.ichiki.json` の3つを聞かれます。** 上で控えた値をそのまま
答えてください。Enter で候補（Local から自動検出したもの）をそのまま使えます。
`wp_root` / `local_site_container` / `site_url` は**この案件を動かす環境ごとに違う値**
（あなたの Local のどこにサイトを作ったか）なので、機械では決められず、ここだけ人に聞きます。

聞かれなかった（対話できない環境で実行した等）ときは、`.ichiki.json` を直接編集してください。

```jsonc
"wp_root": "/Users/…/Local Sites",
"local_site_container": "mysite",
"site_url": "http://localhost:10000"
```

> **手で編集するときは、Windows のパスを `/`（フォワードスラッシュ）で書いてください。**
> `C:\Users\…\Local Sites` のように `\` を1つで書くと、JSON では `\t` `\n` の
> ような制御文字として解釈されます。パースが失敗すればまだ気づけますが、
> `\t` `\n` `\r` は**パースが通ってしまい、値が静かに壊れます**
> （実測: `C:\temp\newsite` が読み込むとタブ文字・改行文字を含む壊れた
> パスになっていた）。`C:/Users/…/Local Sites` のように書けば動きます。
> 対話で答えたときはこの心配はありません（自動でエスケープされます）。

終わったかどうかは、これで分かります。

```bash
node .claude/ichiki/bin/ichiki.js doctor
```

`問題ありません。` と出れば終わりです。出ない項目には直し方が書いてあります。
**手元の道具（node / npm / git / php / wp-cli）とサイトに繋がるかも見ます。**

上のコマンドは何度流しても既存のファイルを壊しません。更新のときも同じものを流せます。

## 詰まったとき

### `node が古すぎます` と言われた

24 以上に上げてください。WordPress 側の制約ではなく、Ichiki 自体
（node で書かれている）だけの話です。

**nodejs.org のインストーラで入れた人（前提）**

1. https://nodejs.org/ja を開く
2. LTS版（24.x）のインストーラをダウンロード
3. 実行する（Mac: `.pkg` / Windows: `.msi`）。既存のバージョンは自動で上書きされる
4. **ターミナルを開き直して** `node -v` で確認する
   （開いたままのターミナルには PATH の更新が反映されない）

<details><summary>nvm / Homebrew で入れている人</summary>

```bash
# nvm（nvm-windows も同じコマンド）
nvm install 24
nvm use 24
nvm alias default 24   # 新しいターミナルでも既定を24にする

# Homebrew（Mac）
brew upgrade node
```

</details>

### `セットアップが終わっていません` / `Cannot find module 'cheerio'` が出た

依存が入っていません。**案件のルートで**セットアップを流してください。
依存も、見た目の比較に使う chromium も、これ一つで入ります（初回は数分）。

```bash
node .claude/ichiki/bin/setup.js
```

### `Cannot find module '...\.claude\ichiki\.claude\ichiki\bin\ichiki.js'`

パスが二重になっています。**`.claude/ichiki` の中にいます。**
コマンドは案件のルートで叩きます。

```bash
cd <案件のルート>
node .claude/ichiki/bin/ichiki.js doctor
```

`.claude/ichiki` の中で叩くと Ichiki 自身のファイルを読んでしまうため、
気づかずに進めないよう Ichiki 側で止めています。

### `.claude/ichiki` の中が空

submodule が取り込まれていません。

```bash
git submodule update --init --recursive
```

クローンするときに `--recurse-submodules` を付けると、これが要らなくなります。

### `.ichiki.json` が無い / `モックの場所が分かりません` と出る

案件の設定がまだ作られていません。`scan` を1回回すと作られます。

```bash
node .claude/ichiki/bin/ichiki.js scan <モックのディレクトリ> <出力先>
```

`wp_root` / `local_site_container` / `site_url` は**あなたの環境の値**なので空で出ます。
[上の「Local でサイトを用意する」](#local-でサイトを用意する)で控えた値を書き足してください。

```jsonc
"wp_root": "/Users/…/Local Sites",
"local_site_container": "mysite",
"site_url": "http://localhost:10000"
```

Windows のパスは `/` で書いてください（`\` を1つで書くと壊れます。上の「やること」参照）。

`.ichiki.json` は git に入りません（人によって値が違うため）。
**クローンした人がそれぞれ作ります。**

### スラッシュコマンドが古い動きをする

`.claude/commands/` へのコピーをやり直していません。

```bash
cp .claude/ichiki/commands/*.md .claude/commands/
```

Claude Code は `.claude/commands/` しか見ないので、本体を更新してもコピーし直さないと
古い手順が動き続けます。`doctor` がこのズレを見ています。

### `gate` が `lint` で大量に落ちる

モックでないディレクトリを読んでいることがあります。`.ichiki.json` に足してください。

```jsonc
"not_mockup": ["docs", "scripts", "参考資料"]
```

既定で `docs` と `scripts` は外れています。隠しディレクトリと `node_modules` も外れます。

## 更新するとき

submodule を進めてから、**初回と同じセットアップコマンドを流す**だけです。

```bash
cd .claude/ichiki
git fetch
git checkout origin/main
cd ../..
node .claude/ichiki/bin/ichiki.js setup
```

既存のファイルを壊さないので、初回と同じものを流せます。
`.claude/commands/` のコピーもやり直されます（**忘れると古い手順が動き続けます**）。

`.ichiki.json` の `ichiki_version` も自動で揃います。
やり直したかどうかは `doctor` が見ています。
