# WordPress にする・検査する

> [案件のトップに戻る](../../../README.md)（やりたいことから探せます）

覚えるコマンドは2つです。

```bash
node .claude/ichiki/bin/ichiki.js gate      # モック → テーマ（サイトは要らない）
#   ここでテーマを WordPress に入れる
node .claude/ichiki/bin/ichiki.js deliver   # 公開後の検査 → 検収成果物 → リリース手順書
```

引数は要りません。モックの場所もサイトの URL も `.ichiki.json` が持っています。

---

## 1. `gate` — モックからテーマを作る

順に流して、最初に落ちたところで止まります。

```
✓ ルール同期      規約と実装が揃っているか
✓ lint            モックが規約どおりか
✗ a11y            アクセシビリティ（落ちても変換は続行）
✓ scan            フィールド台帳を出す
✓ 変換            テーマを作る
✓ フィールド突合   宣言したものが出力されているか
✓ 構造忠実性      モックの class が消えていないか
✓ php -l          PHP の文法
```

**`✓` でも「警告 N 件」が出ることがあります。** 通ったから見なくてよい、ではありません。

### 落ちたら

出力に「どのファイルの何行目が、なぜ駄目か」が出ます。AI に貼れば直せます。
モックを直したら `gate` を回し直します。

### a11y が落ちるのは？

色のコントラストなどは**デザインの問題**で、変換とは無関係です。
落ちても続行しますが、直すかどうかは別途判断してください。

---

## 2. テーマを WordPress に入れる

`gate` はテーマを一時ディレクトリに出します。置き場所を指定して作り直してください。

```bash
node .claude/ichiki/bin/ichiki.js build . <WordPressのthemes>/<テーマ名>
```

テーマ名は `.ichiki.json` の `theme_slug` です。

有効化したあと、**管理画面を1回開いてください。** 固定ページ・投稿・フォーム・
メニュー・サイト名が自動で作られます。パーマリンクも自動で反映されます。

---

## 3. `deliver` — 検査して成果物を出す

**動いている WordPress が要ります。**

```
✓ 公開後の検証     宣言どおりに出ているか
✓ 見た目の比較     モック ↔ 実サイト（数分かかります）
✓ アクセシビリティ
✓ 検収成果物       C1 / C3 / 検収ガイド
✓ リリース手順書
```

順番に依存があります。見た目とアクセシビリティを先に測らないと、
検収成果物が「未実行」で出ます。**`deliver` はその順番を守ります。**

撮影を飛ばすなら `--no-visual` を付けます（速いですが、C1 の表示確認が「未実行」になります）。

### 落ちても成果物は出ます

リンク切れやアクセシビリティ違反は**検収の記録に残すもの**で、直すかどうかは別の判断です。
成果物を出さない理由になりません。

---

## 出るもの

| | 誰が使うか |
|---|---|
| `docs/検収/l1-checklist.tsv` | 社内スタッフ。目で見て判定を書き込む |
| `docs/検収/l1-guide.html` | 同上。使い方 |
| `docs/検収/test-spec.md` | 開発。自動判定の結果を含む全記録 |
| `docs/リリース手順書.md` | 本番へ載せる人 |

**お客様は使いません。** お客様が見るのは、合意までのモックと、納品後のサイトだけです。

---

## 詰まったとき

### `gate` が引数無しで動かない

`.ichiki.json` の `mockup` が実際の場所を指していません。

### `deliver` がサイトに繋がらない

`.ichiki.json` の `site_url` を確認してください。Local はポートが変わることがあります。

### C1 が「未実行」だらけ

見た目とアクセシビリティのレポートがありません。`deliver` を使えば順番どおり流れます。
個別に叩いたときは、`diff` と `a11y --site` を先に回してください。
