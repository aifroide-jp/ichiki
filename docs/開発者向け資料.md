# 開発者向け資料

> [Ichiki の README に戻る](../README.md)

Ichiki を直すときに読んでください。ここに Ichiki 開発者向けの一次情報を集めています。

---

## Ichiki の考え方

デザインは主観なので人がモックで合意する。構造は客観なので機械が検査する。
その境目を **モック側の宣言（`data-*`）** で引く。

```html
<body data-page="single" data-cpt="spot">
  <section data-section="detail">
    <h1 data-acf="hero_title">平尾台</h1>
```

宣言があれば推測は要らない。**宣言が足りなければエラーで停止する。** 推測して埋めない。

規約は `rules/vocabulary.md`（L01〜L31）が**唯一の正**。lint がその実装で、
両者はルールIDで対応する。`selftest` がズレを検出する。

`prompts/mockup-generation.md`（AI にモックを作らせる指示書）は**規約を持たない。**
「まず vocabulary.md を読む」と指示するだけ。以前は規約を再掲していたが、
語彙が育つたびに両方を直すことになり、`data-acf-type` 15箇所 / `wysiwyg` 20箇所が
二重に書かれていた。**ルールは1次参照だけにする。**

`rules/` の2ファイルは書くことを分けている。**同じことを2箇所に書かない。**

| | 中身 | 重複したら |
|---|---|---|
| `ichiki.md` | 前提・環境・成果物・運用の約束 | 要点だけ書いて vocabulary.md の節番号を指す |
| `vocabulary.md` | モックの書き方（宣言と L01〜L31） | ここが正 |

実測で、命名規則・タブ分類・繰り返し・共通領域の判定の4箇所が、
実装が変わったあとも `ichiki.md` に旧方式のまま残っていた。**両方に詳細を書くと必ずズレる。**

## 構成

```
bin/ichiki.js     単一入口。使えるものは全部 --help に出る
src/
  lint/           規約への適合（L01〜L31）
  scan.js         → acf-map.yaml / coverage.json / CLAUDE.md（読み取りは converter/ を使う）
  converter/      → WordPress テーマ
  verify/         coverage（宣言→出力）/ structure（class の維持）/ live（公開後）
  a11y/           pa11y + axe（WCAG2AA）
  visual/         compare（元モック↔制約モック）/ diff（モック↔WP）/ crop
  testspec/       C1 テスト仕様書 / C3 検収シート / C3付録
  shared/         lint と変換器が共有する定数・分類・パス正規化
  gate.js         上を順に流す
  snapshot.js     出力を凍結し、変わったら落とす
rules/
  ichiki.md       前提・環境・成果物の規定・運用の約束（案件をどう進めるか）
  vocabulary.md   モックの書き方 L01〜L31 と宣言の一覧（モックをどう書くか）
prompts/          モックアップ生成プロンプト（規約は持たない。vocabulary.md を読ませる）
templates/        案件用 CLAUDE.md のテンプレート
commands/         Claude Code のスラッシュコマンド（/setup /run）
test/             fixture / mockup-bad / expected と自己検査
```

---

## セットアップコマンドが何をしているか

```bash
1. 手元の道具を見る（node / npm / git が無ければ入れ方を出して止まる）
2. .claude/ichiki で npm install
3. .claude/ichiki で npx playwright install chromium
4. .claude/ichiki/commands/*.md を .claude/commands/ へコピー
5. scan（.ichiki.json / acf-map.yaml / CLAUDE.md / README.md）
6. doctor
```

## 壊れやすいところ

**同じ壊れ方を何度もしている**ので、パターンとして書き出します。すべて実際に踏んだものです。

---

## 1. 同じことを2箇所が別々に知っている

**いちばん多い壊れ方です。** 片方だけ直されて、静かにズレます。

| 実際に起きたこと | どうなったか |
|---|---|
| scan と変換器が別々にモックを読んでいた | デフォルト値が**39件**ズレた。全部 scan 側の誤り |
| lint と変換器が別々にファイルを探していた | 除外がズレて「lint は通るが変換で落ちる」 |
| `compare.js` と `diff.js` が同じ比較をしていた | 片方は一度も成功していなかった |
| `nkk_page_slug` が2箇所にあった | 片方だけ `_`→`-` 変換を忘れ、リンクが `href=""` に |
| testspec が HTML を正規表現で読んでいた | 見出しを日本語にしただけで壊れた |
| `commands/*.md` と `.claude/commands/` のコピーが別々 | `run.md` を新手順へ書き換えたのに案件側は古いコピーのままで、旧手順（AI が1ページずつテンプレートを書く）が動き続けた。書き換えた本人が塞げたと思い込んでいた |

**直し方**: `src/shared/` に1つ置いて両方から使う。
表示（人が読む）と機械可読（JSON）は分ける。

**検査**: `test/check-rule-sync.js` が語彙と lint のズレを見る。
`--acf-map` が台帳と生成物のズレを見る。

---

## 2. 推測している

宣言があるのに読まず、名前や構造から当てている箇所。

| 実際に起きたこと | どうなったか |
|---|---|
| testspec がテーマの PHP を解析してページ種別を推測 | 12ページ中**11ページ**が「種別不明」 |
| `{ news:'nkk_news', events:'nkk_event' }` が本体に焼き込まれていた | 他案件で効かない |
| プロジェクト名を「2つ上のディレクトリ名」から導出 | モックを移した瞬間 `Documents` になった |
| テーマ名を `theme_dir`（環境依存の絶対パス）から導出 | 本番のテーマ名が `nkk-poc` になった |
| 区切り文字を `' | '` `' - '` `' – '` の順に試す | 推測。宣言か設定にすべき |

**直し方**: 宣言（`data-*`）か設定（`.ichiki.json`）から取る。
導出できないなら**止める**。黙って既定値に落とさない。

---

## 3. 既定値が案件の値になっている

引数を渡している限り表に出ません。**省いた瞬間に他案件で違う先を見ます。**

```js
const SITE = (args[1] || 'http://localhost:10004')      // 検証案件のポート
path.join(ROOT, 'mockup-real')                          // 移設で消えたディレクトリ
```

**直し方**: 既定は `.ichiki.json` から取る。無ければ「引数で渡すか設定に書け」で止める。

**検査**: `grep -rn "localhost:1[0-9]\{4\}" src/` で焼き込みが見つかる。

---

## 4. 検査が通っていても検査自体が壊れている

**通ったから正しい、ではありません。**

| 実際に起きたこと | どうなったか |
|---|---|
| フィールド突合が名前で照合、出力はキー指定 | **3/327** で「通った」と言い続けていた |
| `gate --visual` が引数なしで呼んでいた | 一度も成功していない。`blocking:false` で気づけない |
| testspec が存在しないパスのレポートを読んでいた | 常に「未実行」に縮退。安全側なので気づけない |
| 凍結が日付で毎日落ちる | 「また落ちてる」で `--update` が惰性になる |

**直し方**: `test/verify-rules.js`（負のテスト）で「全ルールが実際に違反を検出できるか」を見る。
縮退（安全側に倒れる）実装は、縮退したことを**出力に出す**。

---

## 5. 通ったステップの警告が消える

`gate` は各段の出力を捨てます。`warn` にしただけでは誰にも見えません。

> 実測: デフォルト値の食い違い39件を `warn` にしたが、gate には `✓` としか出ず、
> 「問題が出るようにした」つもりで隠れていた。

**直し方**: 通った段でも警告の**件数**を出す。件数は各段の自己申告（`警告 N 件`）を採る
（行を数えると見出しまで数える）。

---

## 6. 生成物が「それらしく」見えて壊れている

文字列フィールドは ACF がデフォルト値を返すので、**壊れていても画面は正しく見えます。**

| 実際に起きたこと | 気づいた理由 |
|---|---|
| `get_field()` に投稿 ID が無い（36箇所） | 画像だけ壊れた（image 型はデフォルトを持てない） |
| 画像がメディアライブラリに入らない | 同上 |
| url 型のデフォルトがページ相対 | 全ページ `href="http://../contact/"`。**ピクセル比較では出ない** |

**直し方**: `verify:live` で実サイトを見る。`diff` でピクセルを見る。
生成物を読むだけでは足りません。

## テストを厚くしている場所

上の裏返しです。**このうち上3つをまとめて回すのが `node .claude/ichiki/bin/ichiki.js selftest` です。**
（案件を回す人向けの `doctor` とは別物。`selftest` は Ichiki 自身の健全性を見る）

| | 何を守っているか |
|---|---|
| `test/verify-rules.js` | 全ルールが違反を検出できる（検査自体の検査） |
| `test/check-rule-sync.js` | 語彙と lint の同期 |
| `test/run.js` | scan の回帰（fixture ↔ expected） |
| `snapshot` | 出力の凍結。**ページを1枚足したとき既存が動かないこと**を見る |
| `--acf-map` の突き合わせ | 台帳と生成物のズレ。1件でも違えば停止 |
| `verify:live` | 宣言が実サイトに出ているか |

**凍結が効く理由**: 13ページ目を足すと、増えるのはそのページの3ファイルだけで、
既存12ページのテンプレートと ACF は1つも変わりません。
変わるのは集約ファイル（`functions.php` / `seed-*.php`）だけです。
つまり「既存ページが動いたら事故」という信号が取れます。
