# /run — Ichiki Phase 1

モックアップから WordPress テーマを生成する。

引数:

- `$1` = モックのディレクトリ（省略時は `.ichiki.json` の `mockup`）

## この工程で AI は判断しない

**テンプレートを書かない。** 変換器が宣言（`data-*`）を読んで機械的に出力する。  
同じモックなら毎回同じテーマになる。

以前はこのファイルが「1ページずつ AI がテンプレートと ACF 定義を書く手順書」だった。  
その方式は次の理由で置き換えた。

- 出力が毎回変わり、**何が正しいのか誰にも分からなかった**
- お手本に倣うという指示は、倣えているかを機械で確かめられない
- 実測で、名前引きの `the_field()`・CF7 内の死んだフィールド・Web フォントの欠落など、  
  生成物を読むまで気づけない不具合が積み上がった

いまは変換器が担当し、**宣言が足りなければエラーで停止する**。推測して埋めない。

## 手順

1. 検証ゲートを流す。**これ1本で lint から php -l まで通る。**

   ```bash
   node ./.claude/ichiki/bin/ichiki.js gate $1
   ```

   落ちたら、その段階の出力を読んで**モックを直す**。テーマを手で直さない。  
   モックが唯一の入力元であり、テーマはその出力にすぎない。

2. 通ったらテーマを書き出す。

   ```bash
   node ./.claude/ichiki/bin/ichiki.js scan  $1 <出力先>
   node ./.claude/ichiki/bin/ichiki.js build $1 <テーマの置き場所> --acf-map <出力先>/acf-map.yaml
   ```

   `theme_dir` は `.ichiki.json` にある。

3. WordPress に反映する。テーマを有効化し、管理画面を一度開くと  
   固定ページ・CPT 記事・CF7 フォーム・メニューが自動で入る。

   ```bash
   wp theme activate <テーマ名>
   wp eval 'do_action("admin_init");'
   wp rewrite flush
   ```

4. 公開後のサイトを検証する。

   ```bash
   node ./.claude/ichiki/bin/ichiki.js verify:live $1 <サイトURL>
   ```

## 落ちたときの読み方

| 段階 | 意味 | 直す場所 |
|---|---|---|
| lint | モックが制約語彙に適合していない | **モック** |
| scan | 宣言が足りず acf-map.yaml を作れない | **モック** |
| 変換 | 宣言から出力を決められない、または acf-map.yaml と食い違う | **モック** |
| フィールド突合 | 宣言したのに `the_field()` が出ていない | **変換器のバグ** |
| 構造忠実性 | モックの class が生成物から消えた | **変換器のバグ** |
| php -l | 文法エラー | **変換器のバグ** |

**上3つはモック、下3つは変換器。** テーマを手で直して通すのは、どちらの場合も誤り。

## 守ること

- **テーマを手で編集しない。** モックを直して変換し直す。  
  手で直すと次の変換で消え、しかも消えたことに気づけない。  
- **`--allow-unresolved-links` を本番で使わない。** モック＝全ページが前提なので、  
  未解決リンクは本当の不具合。  
- 変換器が扱えない構造に出会ったら、**モックを直すか変換器を直す。**  
  AI が代わりに書いて埋めない。それをやると決定的でなくなる。
